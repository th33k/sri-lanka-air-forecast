# Sri Lanka Air Quality: Ensemble Forecasting Framework

A machine learning framework for forecasting daily air quality (US AQI) for today and tomorrow across all 339 Divisional Secretariat Divisions (DSDs) in Sri Lanka, evaluating **bagging, boosting, stacking, and hybrid** architectures (Random Forest, Extra Trees, XGBoost, LightGBM, CatBoost, ARIMA, ANN).

* **Source Data**: [dataset-sri-lanka-air-quality](https://github.com/th33k/dataset-sri-lanka-air-quality) (Copernicus CAMS model data via Open-Meteo, CC BY 4.0). Values are model estimates on a ~45 km grid, not station readings; DSDs in the same grid cell are grouped into zones (currently 47).
* **Notebook** (the core of the project): `notebooks/air_quality_forecasting.ipynb`. Self-contained and Colab-ready: data checks, exploration, bagging, boosting and stacking, RF vs boosting with a bootstrap significance check, RF + ARIMA / ANN / boosting hybrids, final comparison and conclusions. Runs top to bottom in about 10 minutes.
* **Dashboard**: `uv run streamlit run app.py`

**Forecasting tomorrow.** The dataset holds complete days only, so its latest day is
yesterday. The dashboard therefore offers two forecasts from that day: **today**
(1 day ahead, the model above) and **tomorrow** (2 days ahead, `models/best_tomorrow.joblib`,
the same model trained on a 2-day target). Accuracy drops with the longer horizon; both
are scored on the same unseen hold-out and saved in `results/best.json`.

## Running

```bash
uv sync                                  # or: pip install -r requirements.txt
uv run python -m src.prepare_data        # refresh data/ from the latest dataset
uv run streamlit run app.py              # launch the dashboard
```

To run the notebook locally (or open it in Google Colab, which loads the data from GitHub):

```bash
uv sync --group notebook
uv run jupyter nbconvert --execute --to notebook --inplace notebooks/air_quality_forecasting.ipynb
```

`prepare_data` reads the dataset from a sibling clone of
`dataset-sri-lanka-air-quality` if present, otherwise from GitHub.

### Keeping it up to date

- **Daily (automatic):** `.github/workflows/refresh_data.yml` runs at 05:00 AM Sri Lanka time (23:30 UTC), after
  the dataset repo updates. It rebuilds `data/` and commits it, so the dashboard
  forecasts from the latest day.
- **Monthly (automatic):** `.github/workflows/retrain.yml` runs on the 1st of each month
  (05:00 UTC). It rebuilds the zones, retrains every model, updates `models/`, `results/`
  and the results table above, and commits them. Run it any time from the Actions tab.
- **Retrain by hand:** the same steps locally, then commit `data/`, `models/`, `results/`
  and `README.md`:
  ```bash
  uv run python -m src.prepare_data --rezone
  uv run python -m src.train
  ```
